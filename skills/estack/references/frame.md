# Frame

Separate the user's exact requirements, your assumptions and unknowns. Recover goal, non-goals, acceptance conditions and current authority from the conversation and applicable rules before asking anything. Ask only a question whose answer changes a consequential choice. For a reversible low-impact choice, state a reasonable assumption and proceed when scope permits.

For ambiguous dictation or several conflicting messages, briefly echo the interpretation. A clear instruction needs no new approval ritual. Later user corrections supersede earlier requirements; record the previous choice as superseded, retain parked topics, and invalidate dependent plans/approvals when their action or scope changes.

Example: “offline; no cloud storage” cannot become a hosted database requirement. “Actually use a JSON file; no database” supersedes an earlier SQLite choice. Do not claim the user selected a framework merely because you selected one.

Persistent records use [contract.json](../contracts/contract.json), especially requirements.origin, supersedes and scope_id. The record documents authority; it cannot grant it.
