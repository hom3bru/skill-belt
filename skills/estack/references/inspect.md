# Inspect

Read applicable repository instructions before edits. Inspect the relevant implementation, callers, interfaces, configuration and tests. Record actual revision plus content/patch identity and dirty-state limitations. Preserve unrelated work. Isolation requirements come from the host, user and repository; an unavailable required worktree blocks dependent writes, not safe reads.

For unfamiliar APIs, identify the project's installed/pinned version and consult current primary documentation. Record target version, observed documentation version, original URL, retrieved date and revalidation deadline. A cached page for another version cannot establish compatibility. Version targeting and cache freshness are estack additions (D13); no Context Hub installation is required.

For source claims distinguish directly inspected implementation, maintainer documentation, supplied summary and index-only records. Popularity measures attention at a date, not efficacy. Aliases and ports are not extra capabilities. Keep hypotheses distinct from observed facts.

On resume, re-inspect changed files and affected callers. If documentation or a lesson expires or targets another revision, revalidate before relying on it. Unknown facts stay unknown; inspect the smallest source that could resolve them.
