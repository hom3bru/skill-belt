# Finish

Reconcile each acceptance condition as passed, failed, inconclusive, blocked or not-run from its evidence; an inconclusive condition is reported with what would settle it, never as passed. State concrete changes, exact checks/counts, unrun work, residual risks and delivered artifacts. Report failures against the regression baseline by name in two lists, new and pre-existing. Report a criterion reserved for a person (`verifier: human`) as awaiting human verification until a human review passes it. List what was ruled out and any surprises, each with its evidence. A partial result is useful when labeled partial. A read-only design can be source-audited without runtime validation.

Before reporting, audit the text you are about to deliver, not the intermediates behind it. Pull its claims, re-measure each number against the receipts, and look for hedges that hardened into facts and proxies read as the real quantity (a file's mtime is not "stale for eighteen months"). Say who checked the deliverable: `fresh` (a fresh reviewer read this text), `intermediates-only` or `none`.

Keep local files, commits, pushed branches, PR creation, merge and deployment as distinct delivery states. “Finish”, “ship-ready” and green CI do not add authority for external side effects. Credentials being present does not authorize inspecting or using them. Do not acquire credentials to complete a readiness assessment.

Before a push to a branch with an open PR or to a protected target, check whether auto-merge or a merge queue is armed. If it is, the push can cause a merge nobody authorized: report it and stop. Changing that setting is itself an action that needs authority. Read delivery state back from the live target; a queued merge or an auto-merge request is not a merge. A turn ending with live background work is not done; a host stop guard blocks once, then lets it end and records the gap.

A verified state requires current passing evidence for all required criteria and any required independent review of the same patch; a work unit reads done only on the same terms; blocked and deferred need a reason; every planned item ends in one terminal outcome. A completion marker or caller assertion cannot substitute. Validation is not verification: the helper checks consistency only. Accepting a known failure or risk stores a snapshot of what was accepted; an edit resurfaces it; a malformed marker counts as absent.

When blocked, name action, target, precise reason, completed work and whether the outcome is denied, pending or uncertain. Continue unaffected authorized work. Provide a safe next step without claiming a forbidden action happened.
