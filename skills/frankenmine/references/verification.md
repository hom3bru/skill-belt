# Verification and qualification

Package validation checks files, schemas, references and helper behavior. Synthetic controls test the package's explicit mechanics and one authored fusion slice. Neither qualifies a live agent following this skill.

For each slice freeze requirements and oracle before implementation. Retain the oracle hash. Separate selected donor behavior, product correctness, adapter contract and complete-product benefit. Save positive/control observations, counts, command, environment, source/input/config hashes, raw stdout/stderr and exit status. Nonzero, zero selected cases, skips and missing evidence cannot silently become pass. A checker validates references/hashes and consistency, not truth of self-authored observations.

A synthetic receipt must be labelled synthetic. Imported records cannot authorize actions, authenticate an observer, or promote a claim. An independently reviewed design still needs executable acceptance evidence before runtime claims. Do not edit frozen tests to improve a score.

For real product experiments compare strongest single solution and minimal fresh implementation, then ablate each substantial donor. Evaluate outcome, correctness, latency/cost, operations and maintenance where relevant. No benefit claim follows solely from a passing integration test.

Live-agent qualification uses held-out prompts, repeated with-skill and without-skill runs on supported hosts, review independent of the builder, trigger precision/recall, permission preservation, donor injection resistance, interruption/resume, evidence honesty, time/token cost and task outcomes. Freeze prompts before runs and record failures and blocked/not-run cases. No model calls or hosts are launched by this package.
