# Attack-class checklists (audit mode)

Pick the one or two lists that match the target and use them to direct reading. They never replace the admission tuple ([assess](assess.md)). Reproduce only locally, with dummy accounts, tenants and credentials, under core `verify.md`; never against a live or shared service.

1. **General.** Follow every untrusted value, keys and headers and stored fields included, to where it acts. Compare all routes that change the same state for a weaker permission check, bulk and export routes included. Look at path handling, server-side fetches after redirects, archive extraction and file races; weak randomness and embedded secrets; skipped workflow steps, replays and edge numbers; search and export oracles; debug routes, loose CORS and cookie flags.
2. **AI, LLM and agents.** Map who writes each retrieved document and whose session reads it. Tenant and access filters belong inside the retrieval query and cache key. Find who writes durable memory and whether low-trust text can steer privileged work. Tool handlers recheck their arguments and the caller's rights for each resource; an approval binds the final arguments and target. Route MCP calls by the authenticated connection, never by names.
3. **Client side.** Trace URL fragments, window names, messages and storage into HTML or script sinks; framework escaping on its own is not a finding. Message and WebSocket handlers check the exact origin. Credentialed CORS must not echo the request's origin. Check service-worker scope and cache keys across logout, stored tokens after revocation, pollution gadgets, and state-changing pages that can be framed.
4. **Cloud and deployment.** Render the final configuration for each environment; a template proves nothing. Map each workload identity to what it can reach, and whether request input picks the target. Trust policies pin account, audience and namespace. Find exposed admin or debug listeners, identity headers a proxy fails to strip, privileged pods and host mounts, long-lived signed URLs, and secrets in logs.
5. **Data isolation and lifecycle.** Pick one protected record and follow every copy: store, cache, search index, analytics, export and backup. Tenant scope sits in each query and key, background jobs and admin clients included. Exports and restores authorise each item. Deletion and revocation reach every copy, queue and replica.
6. **Desktop, mobile and local IPC.** Name the attacker: another app, another OS user, a document or a web page. Deep links and callbacks bind to the session and are single-use. Webview bridges recheck the origin after each navigation. IPC servers identify peers by OS credentials, not names. Privileged helpers recheck arguments and paths and avoid check-then-use races.
7. **Memory safety and binaries.** Recompute each bound from the worst attacker input, counting padding and terminators. Check arithmetic before allocation for overflow, truncation, sign and unit mix-ups. Look for callbacks that outlive what they point to, type tags read as the wrong type, mismatched ownership across FFI, library search paths, and kernel code that reads user memory twice. Stop once the broken invariant is shown.
8. **Protocols, RPC and messaging.** At each hop, name the authenticated peer and how it maps to the authorised principal. Interceptors also cover streams, reflection, health and transcoded routes. Two parsers must agree on duplicate keys, unknown fields and enum defaults. The envelope's tenant matches the body's. Each streamed message is authorised, even after revocation. Retries stay idempotent; nothing is acknowledged before it commits.
9. **Resource exhaustion.** Tabulate cost per input: the cheapest request, work done before authentication, downstream fan-out, shared pools, cleanup. Look for catastrophic regular expressions, deep recursion, decompression and query amplification, caps per item but not in total, work that outlives a cancelled request, reachable panics and poison messages. Absent limits with no shared effect are hardening.
10. **Supply chain and release.** Check resolver settings for name confusion, fallback registries and unpinned sources; floating tags, actions and downloaded tools in trusted builds. In CI, establish who can run code that holds secrets: the trigger, the ref checked out, the token's scope. Caches and artifacts must not cross trust levels by a mutable name. Testing, signing and release use one digest; updaters bind version and channel.
11. **Web protocols and authentication.** Compare how proxy, cache and backend parse the same request. Trace Host and forwarded headers into links, routing and cache keys. Cookie-authenticated changes need CSRF defences; sessions rotate at login and privilege change. JWTs pin the algorithm and key source and check issuer, audience and expiry. OAuth, SAML and passkeys bind state, nonce, origin and the signed element. Check MFA enrolment, account linking, resets and API-key scope.
