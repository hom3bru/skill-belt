# Changelog

## 1.0.0-alpha.3 (live DX audit), unreleased

A dx audit mode (`references/dx-audit.md`): a built developer product's onboarding tried as its first developer would, on the core's `dx.md` rubric. The browser for web surfaces on the product's own origin, the shell for CLIs (help, rejected-before-work forms and dry runs without asking; installs, writes, sign-ins and network calls only under a grant naming them), product output treated as data. `qacheck.py validate` checks a `westack-dx-record-1` file (a live score needs refs; each time-to-hello-world step carries minutes, a mark and a ref, the steps add up, and the overall mark is the weakest of theirs); `qacheck.py dx` compares a live audit with westack-review's plan record for the same product and persona and alerts where a score falls more than `dx.alert_drop` (2) below the plan or hello world lands in a worse tier. Ideas from gstack's devex-review at the mirror pin. Tests: 49 (11 new); the control raises `alert_drop` past any drop and misses the fall. The description and page were trimmed to stay under 1,150 words and 450 characters; "the planned westack-perf" corrected (built at alpha.46).

## 1.0.0-alpha.2 (monitor mode), unreleased

A monitor mode for after a deploy (`references/monitor.md`): a baseline, then timed re-checks with cache-busting loads; alerts on change against the baseline (page not loading critical, a new console error high, load over twice the baseline medium, a new broken link low), confirmed only on two consecutive checks, with single sightings kept as transient or pending observations and cleared alerts kept as resolved; page and run status broken, degraded or healthy. `qacheck.py monitor` computes it and `expect` checks monitor expectations. No pixel comparison is claimed: gstack's canary at the pin keeps screenshots as evidence only, and so does this. Long windows use the host's loop or a scheduled task under its own grant. Tests: 38; a thresholds copy that confirms on one check fails the persistence test.

## 1.0.0-alpha.1 (fix-loop mode), unreleased

A fix-loop mode, only with an edit grant naming the paths (`references/fix-loop.md`): triage by severity tier, then per issue reproduce, a failing test first where the project has a runner (browser evidence and a stated reason otherwise), the smallest fix, a re-test of the test, the original probe and the nearest happy path, one commit per verified fix only under a commit grant, and a status of verified, best-effort, reverted or deferred. `qacheck.py loop` applies the stop rule from `thresholds.json`: check in every 5 fixes and after a revert; stop after two reverts, an edit to an unrelated file, two wide fixes in a row, only low issues left, or 50 fixes. `validate` checks fix records and `expect` checks `fixed` defects. The stop rule follows gstack's qa at the mirror pin (c1ace748), which replaced the July version's percentage rule. `SKILL.md` gains the fix-loop row and rule and stays within its 1,150-word ceiling (1,138). Tests: 32; a thresholds copy that never stops on reverts fails the stop test.

## 1.0.0-alpha.0 (first build: report-only QA), unreleased

The first westack-qa: QA of a running web app through the host's own browser tools, report-only. Four modes (quick, full, diff-aware, regression), an orient-explore-document run, a severity scale, a 0-100 health score over the tested categories only (provisional when partial, "not scored" when nothing was tested), and a report format that `scripts/qacheck.py` scores, validates, compares and checks against planted defects. Browser use follows the core's `browser.md`; with no driver the run is degraded and claims nothing. Ideas from gstack's qa, qa-only and the shared QA method at the mirror pin (provenance/donors.json), in westack's words; gstack's browser daemon, its telemetry and its TODOS.md updates are left out. Fix-loop mode is the next slice (S5 of the absorption plan). `tests/test_qacheck.py`: 22 tests; a copy of the thresholds with the deduction table zeroed fails the score tests. `evals/fixtures/site` plants four defects for a live run.
