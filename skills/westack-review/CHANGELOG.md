## 1.0.0-alpha.30 (dsh-superagent: DS-1 to DS-3), unreleased

Three rules for resolve mode, from deepseek-ai/dsh-superagent-prototype at `6337fc82` (MIT; ideas only, in westack's words, nothing copied or run), approved by the user ("Brief and send all", 2026-10-31). No SKILL.md change (1,314 words, ceiling 1,320): the rules are in references.

- **DS-1, rounds.** At most three review rounds per automated reviewer on one pull request; a round is one distinct bot run, not one comment, and each run's id and the count are recorded so a later session continues it. `resolve.md` section 1 and the section 6 table (a `round` for bot authors); the detail is in the new `references/threads.md`.
- **DS-2, thread replies.** Reply in each comment's own thread; a top-level comment or PR-body table never replaces thread replies; read the thread first, never repeat an answer or resolve a person's valid open finding (`resolve.md` section 5, `threads.md`).
- **DS-3, the push.** Resolve mode pushes through `westack-ship`'s pre-push check (its rule 1): an armed auto-merge or merge-queue entry stops the push until the user decides, and an unread field counts as armed. GitHub keeps auto-merge on when someone with write access pushes. The check itself is not duplicated: the cross-skill test runs `shipgate.py` on a resolve fixture.
- **`scripts/diffscope.py resolve LEDGER`** (a sixth mode, no diff read): `bot-round-cap`, `bot-run-unknown`, `reply-not-in-thread`, `reply-repeats`. The report's `rounds` go into the next session's ledger. A bot is a flagged comment or a login ending in `[bot]`; `cap` defaults to 3 and the report notes any other value.
- **Pages.** `resolve.md` 698 to 731 words (cap 732, from the 610-word base), by trimming eight words of asides and one repeated `no`; `threads.md` is new, 508 words. Pinned phrases kept.
- **Tests.** `tests/test_threads.py`, 30 (127 in the suite): run first against a stub that reports clean (30 tests, 32 failures, 1 error), then green. Eight broken copies, each built before its assertions: a copy that counts comments fails the seven-comment ledger; one without the cap, one that reads every author as a person, one that assumes a missing run id is a known round, one that forgets earlier sessions' rounds, one without the thread check, one without the repeat check, and one that only checks a reply exists fails both reply ledgers.
- **Provenance.** One record (`ds:deepseek-ai/dsh-superagent-prototype`) with the files read at the pin, hashes checked in memory. Not carried: silent resolution of fixed threads, crediting reviewers by rewriting the branch and force-pushing, the bot disclosure line, and the donor's withdraw-auto-merge-before-push step (westack stops the push instead).

Known limits: a reworded repeat passes `reply-repeats`; the run id and the answers are what the agent read, and the check cannot read the forge.

## 1.0.0-alpha.9 (review: CodeRabbit-style checks), unreleased

"Code review like CodeRabbit": the checkable discipline from CodeRabbit's skills, openai/codex-security, anthropics/claude-code-security-review and claude-mem, plus three papers, in westack's own words; and a consented defer to the real CodeRabbit CLI (core `references/defer-map.json`, entry `review-coderabbit-cli`). Ideas only; nothing from any donor was run. The description (exactly 450 characters) and `SKILL.md` are untouched; the router is unchanged.

- RV-1 (`references/code.md` section 4, walk 4): a point-of-use walk. Each control the change adds or relies on must cover the exact value the sink consumes, through redirects, re-encoding, mutation after the check, retries and re-resolution.
- RV-2 (`references/code.md` section 4, lenses): a sibling-control lens. Find how the codebase already handles the risk; a changed path that reaches the sensitive operation without that helper is a finding that cites it.
- RV-3 (`references/rules.md`, after the finding table; `scripts/diffscope.py`): a traced trigger behind a confirmed P0 or P1 quotes its path as `snippets` labelled input, entrypoint, control, sink or outcome. `diffscope.py findings` checks their shape; the new `diffscope.py snippets DIFF FINDINGS [--root DIR]` compares each quote with the cited lines (new side from the diff or a checkout of the head, old side from the diff only), ignoring surrounding whitespace and line endings, so a paraphrase or a moved line differs. Verdicts matches, differs, not-found, not-checkable; exit 0 verified, 1 mismatch, 2 inconclusive, not-run or unreadable. A path that leaves the root is not-found.
- RV-4 (`references/code.md` section 6): the patch is rated on separate axes (impact if wrong, regression likelihood, protection, recoverability, confidence); tests never lower impact.
- RV-5 (`references/rules.md`, finding identity): a dismissal holds only while its stated reason holds against the current source; a bare false-positive label never dismisses.
- RV-6 and RV-13, merged (`references/rules.md`, project review rules): the review-rules file may name checks with a mode, an applicability condition (a path pattern, for example) and requirements; one that does not apply reads not-applicable, never passed; one the change adds or loosens is a finding; path-scoped instructions are read the same way, from the base revision.
- RV-7 and RV-17 (`references/rules.md`, new section Outside reviewers): a delegated or vendor run is complete only with one completion event, a count equal to the records received, a clean exit and no truncation; skipped with zero findings is not-run. Its comments are candidates, never findings or a quality signal, and each run's candidates, confirmed and dropped counts are reported. `diffscope.py findings` refuses a vendor's confirmed record without a westack `validation` and prints per-vendor counts with the dropped share. The field study behind RV-17 (2607.03316) is cited only in the donor record, graded claimed.
- RV-8 (`references/rules.md`, Outside reviewers; `scripts/diffscope.py`): a vendor's severity label is kept verbatim in `vendor_severity` beside `vendor`; missing is unknown, never low; P levels only after validation. The schema refuses a label without the vendor's name and an empty label.
- RV-9 (`references/resolve.md` section 1): act only on unresolved, not-outdated threads started by the named reviewer, keep each thread's id, follow pagination, wait while the reviewer runs, warn about unpushed commits.
- RV-10 (`references/rules.md`, finding identity; `scripts/diffscope.py`): in code, identity is a rule family, the root control's anchor and an instance key per independently attackable sibling; group only when control and fix match, never by a shared CWE. The schema's optional `identity` refuses an anchor with a line number and two open records with one identity (a drop may repeat the identity it merged).
- RV-11 (`references/rules.md`, after the findings check, instead of `SKILL.md` section 3, which is over its word guide): a confirmed P0 or P1 makes the verdict blocking whatever else is missing; not-assessed names at most three actions, each with what it would settle. `diffscope.py findings` refuses not-assessed beside a confirmed P0 or P1 and checks the optional `evidence_plan` (one to three actions with `settles`, only with not-assessed). It stays optional so earlier saved output still validates.
- RV-12 (`references/resolve.md` section 4): a fix is admitted only if it corrects the logic at the cause, sized to the defect; wrapping the defect in a guard, fallback, retry, watchdog or truncation is a finding.
- RV-16 (`references/rules.md` validation step 2; `references/code.md` section 1): the validator's packet is the diff, a written summary of intent and the files on the path, never the whole repository, and the page says that a shorter packet finding more is not yet measured; a model's silence about a file is not coverage, only the ledger's mark is.
- RV-18 (`references/rules.md` validation step 3): a candidate that names the right file but argues a cause its trigger does not show is dropped, mechanism not demonstrated; credit the mechanism, never the file alone.
- RV-14 and RV-15 are core (`references/defer.md`, Deciding step 1) and listed in the core changelog.
- Evals: routing case r23 ("Review this PR with CodeRabbit before I merge it." expects westack-review; the installed CodeRabbit skill is its likeliest misroute). Task cases `vendor-consent` (asks first, naming CodeRabbit, the upload and the sandbox exit) and `vendor-declined` (its own review runs and CodeRabbit is recorded not-run), each with a forbidden rule against any CodeRabbit CLI call, on the seeded-diff fixture; `campaign.py validate` passes. ## 1.0.0-alpha.4 (P1 adoption), unreleased

- **SS-01.** A dropped or downgraded finding keeps a visible record. The report lists each drop with its claim, reason and deciding evidence, and every candidate id appears once, as a finding, a drop or not validated. A model verdict may downgrade with a stated reason but never deletes deterministic tool output, and a worker's all-clear is input to audit, not a result.
