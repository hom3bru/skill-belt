# Networking and outreach

For explicitly selected private context, read [loadable user context](../../context/README.md).
Read [message patterns](references/message-patterns.md) and
[integrity and safety](../../references/integrity-and-safety.md). Current instructions and live
permissions decide whether anything is sent.

1. **Establish who, why and how you know them.** Settle the recipient, their actual role, how the
   user knows them (a colleague, an alum, met at an event, a stranger), and the one thing the user
   wants. Never invent a shared connection, a past conversation or familiarity. When the
   relationship is unknown, write it as a cold message.
2. **Use verified, dated specifics.** Personalise only with facts you can source: the posting, the
   person's public professional work, or the user's real shared history. Note where each fact came
   from. Do not use private or scraped personal contact details. Respect any "do not contact"
   request or stated recruiter process.
3. **Make one clear, easy ask.** Write the shortest message that gives context, says why this person,
   states the ask, and gives an easy way to say no. A referral request includes the exact role
   link and a two-to-three-line case the referrer can forward. That case must be checked against
   evidence, just as a cover letter is.
4. **Check the draft.** Check the facts against the user's evidence, check the tone against the
   relationship, and check that the message stays within any employer rules. Do not pressure,
   flatter dishonestly or create false urgency.
5. **Deliver the draft and a suggested timing.** For example: one follow-up after the stated
   timeline passes, or about a week after an application if no timeline was given; thank-you notes
   within a day. Sending, scheduling or connecting on a platform needs the user's current
   instruction and a real tool. Report receipts, not intentions.
6. **Keep continuity.** If the user authorises it, log the contact in the canonical tracker against
   the right record: date, channel, person and outcome. Before suggesting another follow-up, check
   earlier messages so the user does not repeat themselves or chase someone who has already replied.

Never message on the user's behalf in real time, impersonate the user in a live conversation, or
send bulk messages. A drafted message is not a sent message, and a reply the user hoped for is not
a commitment from the employer.
