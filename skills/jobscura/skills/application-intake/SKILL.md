# Job intake and assessment

For explicitly selected private context, read [loadable user context](../../context/README.md).
Current user instructions and live permissions override saved preferences.


Give a useful, evidence-based recommendation without creating a second tracker or
confusing a saved job, a viable opportunity and a submitted application.
Read [tools and continuity](../application-writing/references/tools-and-continuity.md)
and [evidence and currentness](../application-writing/references/evidence-and-currentness.md).
The workflow works with a supplied posting and candidate materials even without a
connected runtime. Use only actually available tools and report unsaved work honestly.

1. Resolve the intended opportunity and the user's current request. Extract the
   employer, role, requisition or official URL, location, closing date and required
   qualifications from the source. Read the full posting when accessible. Separate
   essential criteria from preferences, responsibilities and marketing language.
2. If current availability matters, check the employer's official source through
   available browsing/search tools. Preserve the observation date and uncertainty.
   A saved page or aggregator listing alone does not prove it is still open.
3. Find the existing canonical tracker and relevant prior assessments through
   available file/search tools. Use exact URLs or requisition evidence for identity;
   company/title similarity alone is insufficient. Distinguish a duplicate listing,
   a new posting of an old role and a separate application. Preserve existing rows
   and the tracker system rather than starting another spreadsheet or database.
4. Retrieve the relevant current career evidence, corrections and intent. Review
   requirement by requirement using [assessment method](references/assessment-method.md).
   Keep supported experience, credible transfer, unknowns and actual gaps distinct.
   Ask only for an unknown that could materially change the decision.
5. Deliver a concise recommendation with the most consequential reasons, evidence,
   uncertainties and next step. Keep qualification gap, evidence confidence,
   direction/interest fit, availability and pay/location constraints separate.
   Use the user's existing scoring convention if available; do not invent neutral
   scores when evidence or a rating method is missing.
6. Apply current user instructions and permissions to any requested tracker action.
   If an add/update is authorized and a suitable edit route is available, read the
   current version, preserve canonical structure and user edits, perform only the
   authorized change and verify it. Otherwise provide the assessment and proposed
   row/update with its unsaved status. Never infer standing approval from this skill.

If an existing selected runtime supplies exact-version intake and assessment
checks, honor them. A retained assessment is historical until its current support
has been checked. Do not silently regrade old jobs or rebuild stale records through
an invented tool. Tracker edits, external outreach and application submission are
separate actions governed by the user's current request and permissions.


For repeatable source capture and deterministic read-only matching to the existing
tracker, use [application-packet](../application-packet/SKILL.md) when an authorized
executor is available. Its match status is not a qualification assessment, tracker
edit or authorization to submit. Keep missing and ambiguous identities pending.

For status audits, deadline countdowns, retirement, reposts, Stretch-list routing
and morning job changes, read [application tracking](../application-tracking/SKILL.md).
It supplements this intake workflow and does not grant tracker or outreach authority.
