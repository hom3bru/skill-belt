# Check the final candidate

Review the exact version being delivered. Keep factual support, editorial quality,
requirements, mechanics, visual layout and artifact integrity distinct. Passing
one does not establish the others; absence of a checker is not a pass.

- Factual support: compare consequential claims to actual source spans, preserving
  authority, scale, actor, timing, attribution, causality and uncertainty.
- Editorial quality: read the full argument against purpose and current intent.
  Assess selection, progression, proportion, stance and voice in context. This is
  a fallible judgment, not something a keyword count certifies.
- Requirements: answer every required subpart and respect actual limits, locked
  fields, titles and requested format. Check the target form's counting convention
  if a limit is close and consequential.
- Mechanics: inspect grammar, repetition and local phrasing without changing the
  meaning or making protected edits.
- Layout: for a file, inspect every page and reading order in an available renderer.
  If that cannot run, say layout was not verified; text extraction is not visual QA.
- Artifact identity: verify that the final saved/exported artifact contains the
  intended text and corresponds to the reviewed version. A filename or earlier
  screenshot does not prove this. Do not reuse review results after an edit without
  checking what changed.

For employer or third-party facts in a letter or answer, including named products,
programmes, people, papers and news, provide a dated official source the user can
inspect. Flag any fact without that support as unverified before delivery.

For each lead claim, check that the user could explain the work to an interviewer
for about two minutes. If the evidence establishes only proximity to the work,
soften the claim or choose a better-supported lead.

After each revision, compare employer, title, dates, degree and contact fields
against the source: they must remain unchanged. Check that no employer, role or
team name from another application remains in the candidate being delivered.

Use suitable available document tools for the requested destination. Preserve the
canonical file and existing sharing boundaries. Deliver a verified accessible file
or link when supported, otherwise complete text in the conversation. Never present
a private machine path as a delivered attachment.

Briefly state important changes, unresolved material issues and any significant
unrun check. Keep detailed source comparisons available when useful without making
the user reconstruct the recommended text. Do not add audit notes or defensive
explanations to employer copy unless the employer's question requires them.

A checked draft or prepared attachment is not an application submission, a sent
message, an employer-confirmed interview or approval of a new commitment. Use the
user's current authorization for those separate actions.


When the next task is preparing files for a specific application form, use
[application-packet](../../application-packet/SKILL.md) for byte-bound review records,
exact upload-slot kind/filename checks, a source snapshot and a non-overwriting
packet manifest. This supplements rather than replaces the factual, editorial and
rendered layout checks above. A writing sample is not a cover letter; preserve
the exact requested artifact kind and never relabel one to satisfy another slot.
