## 1.0.0-alpha.39 (audited graders, real quotes), unreleased

`grade.py` and `campaign.py`, for model graders that run in an agent host which cannot hide its tools:
- `grader.tools` other than [] is accepted only with `grader.tools_audit`: someone other than the grader audited its session log (`log`, `method`, `auditor`), held it to a folder (`scope`) and found no read outside it (`reads_outside_scope: []`). The analysis then states that the grader's blindness rests on that audit.

## 1.0.0-alpha.28 (eval: power rechecked at the observed tie rate), unreleased

- `scripts/evalstats.py` `compare`: power is rechecked at the observed tie rate whenever it differs from the declared one, in either direction (the old guard fired only above it, and gated only `better`). Below the power target there, `better`, `worse` and `equivalent` become `inconclusive` with one reason naming both rates and both powers (`underpowered at the observed tie rate`). Reproduction: declared 0.50, 83 cases, 43 wins, 16 losses, 24 ties is no longer `better` (power 0.80 declared, 0.66 observed). An observed rate that raises power changes nothing; an unmoved rate changes nothing. `pool.py` and `campaign.py` both call `compare`.
- `compare` records the verdict it withheld as `withheld_verdict` (only when the recheck withholds one). `campaign.py` reads it in the check that the broken-copy control was judged better (`_control_fooled`), so a control the recheck demotes still invalidates the campaign; a control whose skill arm never engaged is excluded, as before. `pool.py` has no such gate.
- `references/reading-results.md` and `references/protocol.md` now say what the code does (the protocol sentence had the direction backwards).
- Pinned verdict changed: `test_a_versus_a_is_never_better` expected `equivalent` when every case ties; the observed tie rate is 1.00, power 0.00, so it is now `inconclusive`. `ENOUGH` in `test_campaign_run.py`, `test_p1_eval.py` and `test_p2_eval.py` is raised to 26 so their all-win fixtures (observed tie rate 0.0, declared 0.3) stay powered at the observed rate, and the engagement control in `test_p1_eval.py` now asserts `not_engaged`, because the A-versus-A verdict no longer tells its broken copy apart.
- 8 tests in `tools/eval/tests/test_stats.py`, red first (4 failures, 3 on an assertion), with five broken-copy controls built before their assertions: the one-direction check restored, `better`, `worse` and `equivalent` each ungated, and the withheld verdict not recorded. 2 in `tools/eval/tests/test_p1_eval.py`, red first, for the control gate: a fooled control the recheck demotes still invalidates the campaign (broken copy: the gate reads the final verdict), and a never-engaged control does not (broken copy: the exclusion dropped).

## 1.0.0-alpha.27 (eval: pre-registered pooled studies), unreleased

- `scripts/pool.py`: one pre-registered analysis across several paired campaigns, so a stack-wide claim is not chosen after the results are seen. `register POOL_DIR CAMPAIGN_DIR...` writes `pool-prereg.json` once: the sha256 of each member's `prereg.json`, the primary comparison (skill against bare by default), the unit (the case, replicates averaged first), the test (exact one-sided sign test on per-case outcomes and a seeded case-level bootstrap of the mean difference), alpha, power, margin, tie rate, seed, the independence argument, `required_n` and the power at the planned cases, and three secondary metrics declared in advance (hard-fail rate, cost per run, turns per run, each better lower). It refuses a member whose ledger holds a run or a started one; `--post-hoc` registers such a pool, and its record, `verify`, every analysis and every summary line say POST-HOC while its verdict stays descriptive.
- `analyse POOL_DIR` refuses (invalid) a pool whose record was edited, a member whose `prereg.json` bytes changed or that no longer matches its own registration, a run started before the pool, a member whose newest result is not valid or used a sheet other than the registered one, and a member whose re-scoring does not reproduce its own wins, losses, ties and mean difference. It re-scores each member from its sealed mapping exactly as `campaign.py` does, pools the cases (ties stay in n) and runs `evalstats.compare` on them; a one-member pool gives the member's own sign test and bootstrap. Extra gates: descriptive without an independence argument for the pool or any member, or when post-hoc; inconclusive when a member's skill arm never engaged. It reports the pooled verdict, a per-skill table and each secondary metric with the arm that wins it.
- `references/pooled.md` (new, linked from SKILL.md Rules, `reading-results.md` Promoting a change and `protocol.md` step 3).
- 11 tests in `tools/eval/tests/test_pool.py`, all red first against a stub (9 assertion failures, 2 errors), each with a broken-copy control built before its assertion: a refusal switched off, the post-hoc label or gate dropped, the member hash or the start-time check or the reproduction check switched off, a shifted bootstrap seed, ties dropped, runs pooled instead of cases, the secondary winner reversed.
