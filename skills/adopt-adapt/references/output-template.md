# Output template

Quick calls use §1, bounded reviews the [manual ledger](bounded-ledger-template.md), full reviews this template. Retain pairs, decisive evidence, constraints and uncertainty.

Multiple leads require **Decision frontier** before ledgers with check/pair IDs. Rank runnable checks, then decisions resolved. Unconfirmed need requires `Current burden: <recipient observation + evidence, or unobserved>` before `Next check: <recipient-only burden observation if unobserved>` and `Prototype: <conditional on confirmed need>`. Share captures only when one recipient entrypoint/workload supplies every observation. Cite scope, pair criteria and reopened decisions. Separate independent actions, workloads and recipients. Preserve pair evidence, mechanisms and verdicts. Reference check IDs without repetition. Single leads keep this ordering.

Manual WIRED proof, per donor/recipient: `subject | normal activation cite | incoming path cite | mechanism`. The assessed body/proposed invocation cannot prove activation; missing either proof means PRESENT.

1. Manifest line: `#n source → recipient — STATE`
2. Shared donor ledger once: identity, map, read/total coverage, blind spots, relevant subsystem stages, five lenses with evidence. Name pairs for distinct variants. Recipient ledgers reference this basis and record HEAD/dirty files, overlap, due diligence, gates, **LEGAL:** flag/route/ladder/escalation ([legal](legal.md)), closed-source confidence or web-forensics hashes, claim/level/file:line table, TESTED/OBSERVED run receipts, required independent review (level, packet/report hash, strongest disconfirmation), and doubt (against, for, deciding evidence). Inferred claims carry confidence. `aa.py render` emits each claim's `level`.
3. Verdict line: `VERDICT: <ADOPT|ADAPT|ADAPT-with-prerequisite|ALREADY-COVERED|DISCARD|OPPORTUNITY|INCONCLUSIVE> | fit x/10 or not scored | mechanism y/3 | confidence <low|medium|high>` (anchors: SKILL.md §4). A promising but unconfirmed transfer (value 1, one check would confirm the need) prints `DISCARD (promising: <check to run>)` as its result. A pair that is not READY prints `STATE: <BLOCKED|UNPROCESSED|CANCELLED> — reason` instead and no verdict.
4. Plain summary: what it is, the mechanism, recipient benefit, limit, next step.

No final verdict before step 2. Label provisional doubt leanings PROVISIONAL.

For skill/hook/MCP/plugin/config donors, include the [behavior inventory](due-diligence.md#donor-risk-audit-required-for-skill--hook--mcp--agent-config-donors-recommended-for-all) in the shared map and risk classification in `ledger.donor_risks[]`, avoiding repetition.

For RE sources, step 2 includes the [method contract](re-methods.md): method/claim rows, output, original/recovered baseline, inherited/new contribution, distribution boundaries, check status/evidence. Distinguish matching, behavior, readability and portability. Quantified progress includes numerator, denominator and exclusions. Never turn a structural match, compiled build, isolated fixture or claimed donor result into whole-system behavioral verification.
