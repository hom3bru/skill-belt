# adopt-adapt: open mechanism discovery

Assessed for adopt-adapt itself. Primary papers and relevant repository source files were inspected on 2026-11-02 PT. No donor code was executed or imported. These are design inputs, not proof that adopt-adapt improves decisions.

| Work / pinned source | Inspected evidence and limit | Design consequence |
| --- | --- | --- |
| [Retrieved but not ranked](https://arxiv.org/html/2609.01556v1), September 2026; [source](https://github.com/nabirarashid/structural-retrieval/blob/c0eef536e3cab170fd4093963ec13ed04c88c807/src/llm_reranker.py) | Two retrieval domains separate structure from wording. Rankers can favor surface tokens; reranking improves retrieval, without establishing downstream gain in the tested solver. The authors disclose dataset, judge, contamination and headroom limits. | Apparent similarity is a discovery clue, not a value measure. Test actual recipient benefit separately from finding a plausible analogy. |
| [Break It Down, Pass It On](https://arxiv.org/html/2608.20274v2), October 16, 2026 revision; [source](https://github.com/Zesearch/skill-transfer-llm-agents/tree/8317798951716e9bd7c792728b8ca70830734f37) | Three benchmarks and eleven models support modest average gains from subtask text skills relative to their own no-memory agents; task-level recipes often hurt. Applicability and abstraction matter jointly. Repository extraction prompts strongly encourage emitting a function; that production pressure is not adopted here. | Isolate useful mechanisms and preserve assumptions. Keep no-gain outcomes and reject a positive-finding quota. The text/code result is not a general ban on code reuse. |
| [XRepoSkill](https://arxiv.org/html/2609.36807v1), September 29, 2026; [rule specification](https://github.com/XREPOSKILL/XRepoSkill/blob/26fd70345698108c0fdce2d8904293a38b9cd42f/src/xreposkill/prompts/_shared_rules.txt) | Python-derived procedures transfer across repositories/languages in the reported evaluation. The inspected rule specification distinguishes general condition/action rules from concrete local facts. Association with success does not alone establish causation; language subsets vary in size. | Match underlying behavior and conditions rather than source labels. Require a falsifying recipient test instead of inferring gain from donor success. |
| [SkillsBench](https://arxiv.org/html/2602.12670v4), June 14, 2026 revision | Matched no-skill/curated-skill evaluations on 87 tasks across 18 model/harness configurations. Effects vary; compact guidance fares better than exhaustive bundles in the design analyses. Containerized terminal tasks do not qualify every workflow or an optimal universal module count. | Judge additions against the current recipient and account for overhead. Do not add a numeric bloat metric or a new reporting subsystem without evidence. |
| [ARCANA](https://arxiv.org/html/2610.29271v3), October 29, 2026 revision | Far analogies map real-world concepts to abstract grids; model failures remain. The authors state scale, representation and executor limits. This is not a software-transfer benchmark. | Openness to distant connections needs direct behavioral evaluation, including incompatible analogies and missed patterns. |
| [Structure-mapping framework](https://qrg.northwestern.edu/ideas/smeidea.htm), foundational work originating in 1983 | The originating research group's account distinguishes relational alignment from appearance matching. It is a conceptual foundation, not empirical qualification of this skill. | State the source problem, invariant and analogy-breaking assumption without treating domain identity as the mechanism. |

The retained principle is: **Absolutely anything could contain useful parts or patterns. A wildly unrelated source could contain the most valuable mechanism.** No study proves every source contains a worthwhile transfer. Unknown applicability remains open; concrete incompatibility or cost can justify declining a particular transfer.

Implementation uses the existing routing, lessons and transfer-contract seams. The only record extension admits extra evidence-backed discovery areas alongside the five protected starting lenses. Existing `alternatives` prose carries the net-burden account. No paid element, new runtime dependency, donor engine, embedding service or memory system is introduced. Helper tests and independently authored assessments measure local behavior separately from these external findings. The r17 comparison tied at 6/6 cases and 53/54 points for baseline and candidate; it did not establish discovery superiority. Public package checks cover structure and helper behavior, while raw private development and host-session transcripts are omitted from this collection.
