# Public editions

Skill Belt publishes author-owned public editions of adopt-adapt, Frankenmine and westack. Each edition is generated from a release commit of the skill's canonical source by `scripts/build_public.py`, so nothing under `skills/` is edited by hand. Installed skills are never edited.

```sh
python -B scripts/build_public.py [--adopt-adapt DIR] [--frankenmine DIR] [--westack DIR] [--check]
python -B scripts/generate_manifest.py
python -B scripts/verify.py
```

Each `DIR` is the skill directory of a canonical source outside this repository. Read it from the full release commit with `git archive <commit>` and use its `skills/<name>` directory; `git archive <commit>:<subdir>` drops the repository's `.gitattributes` and changes line endings.

The build copies the canonical skill into a staging directory inside this repository and drops the `exclude` globs listed in [public-build.json](../public-build.json). It then applies that skill's overlays: public replacement files under `public-overlays/<skill>/`, each pinned to the SHA-256 of the canonical file it was derived from. An optional `description` override replaces only the SKILL.md description line, pinned the same way. If a pinned canonical file has changed, the build fails until the overlay is re-derived. adopt-adapt's `release.json` is not copied: the build regenerates it with the skill's own `scripts/package.py` after the excludes, so it hashes exactly the published files.

The staged copy must also:

- contain no links or junctions;
- pass the leak-pattern scan and the local-link check;
- carry `references/evidence-vocabulary.md` byte-identical to `shared/evidence-vocabulary.md`, when the skill links to it.

Only when every named skill passes is `skills/<name>` replaced. `--check` stages and checks without replacing anything. The report gives source and edition tree hashes, so a rebuild can be compared byte for byte. Canonical sources are only read. A private identifier that is useless to readers is removed in the canonical source rather than overlaid.

Policy: omit private build and session identifiers, machine-specific transcripts and local audit logs; keep contracts, runnable tests, source URLs and inspection limits.

westack (then called estack) 0.3.0 passed a blind not-worse check; this collection publishes it as westack 0.3.1, the same content under the new name. Frankenmine 0.2.0 and adopt-adapt r16 each passed a pre-registered blind before/after comparison against the version they replace: not worse at 8 pairs each, with no new hard failure. That is the whole claim; it does not establish superiority, general effectiveness or host qualification. The editions carry the versions the skills were released under. They replace the earlier hand-made editions (Frankenmine 0.1.2-portfolio.2, adopt-adapt r13-portfolio.1), and no portfolio suffix is applied because adopt-adapt's own tests pin its version string.

Per-skill manifests identify the published bytes rather than claiming equality with the canonical sources. Skill snapshots and overlays preserve byte fidelity across Git checkout platforms. New validation results should be generated from the current checkout; private historical logs are not bundled as release evidence.

The helpers and synthetic fixtures were independently authored. Source references credit the research lineage and do not imply that third-party implementations are bundled, endorsed or comprehensively qualified. See the skills' research and provenance notes and the root [ownership notice](../NOTICE.md).

Full agent effectiveness, repeated comparative model trials, native host behavior and hostile-filesystem security remain outside the scope of a passing collection check.

## Jobscura

Jobscura 0.4.0 derives from the Application Assistant 0.3.0 workflow source,
including the November 2 tracking update. Its package identifier and six workflow
names remain compatible. The sanitized canonical edition adds a suite router,
loadable user-context schema/example/validator, privacy controls and deterministic
packaging. Private contact metadata, user settings, historical audit material and
the binary tracker fixture are excluded. The fictional XLSX case is generated at
test runtime; packet helper 0.2.1 fixes Windows path representation. No personal
tracker or application records are imported. The collection ownership notice
applies; publication does not grant an open-source license.

Rebuild the edition from its sanitized canonical source with
`python -B scripts/build_public.py --jobscura DIR`, then refresh the collection
manifest and run verification. The private audit archive is not a public build
input and must never be copied wholesale into the repository.

## Current-tree owner anonymization

The owner requested the anonymous label `user` in current attribution and owner
profile references. Copyright, proprietary status, reuse limits and third-party
attribution are preserved. Existing public Git history is not rewritten. The
adopt-adapt edition is regenerated from an isolated r16 release copy with only
the owner label changed in its skill metadata and SELF profile; its public
changelog overlay uses the same label, and release/snapshot hashes are refreshed.

Carrier Pigeon 0.15.1 adds configurable human identity and version-aware legacy
signature/approval handling. Public examples use anonymous identities. Existing
mailbox data and Windows Hello keys are not migrated or modified automatically.
The earlier 0.15.0 live-qualification records remain historical evidence; the
0.15.1 identity work is checked through isolated regression fixtures.
