# Frankenmine 0.1.3 — optional synthesis handoff index

The optional `handoff` CLI projects the existing run record into exact donor/contract/test/receipt joins, source and owner locators, and deterministic pending decisions. Original records, check/report behavior and schema remain authoritative and unchanged. Optional original-manifest joins compare exact IDs and source URLs. Invalid evidence remains explicit; no timestamps exist for temporal freshness. Implementation stages, bounded passing checks, integration evidence and demonstrated benefit remain separate.

Authored acceptance tasks were frozen before implementation in the tracked personal source research record. The additive suite covers interrupted selection and implementation, conflicting ownership, missing integration, failed controls, stale/missing bytes and disconnected provenance/receipt/manifest joins. This release makes no controlled recovery-effort, independent-review, live-agent or runtime-benefit claim. Historical v0.1.2 receipts below remain historical evidence rather than validation of this change. No installation or synchronization is performed by the helper.

## Frankenmine 0.1.2 — product continuation support

This iteration used estack as a representative multi-donor product, rather than making estack-specific rules part of Frankenmine. Generic continuation routing now preserves an existing build/manifest, recovers evidence depth and advances a useful authorized product slice. A lightweight dossier is sufficient when full schema interchange adds no value.

The optional init --decisions helper registers every decision as queued, retains only declared identity/scope notes, and fetches or executes nothing. It rejects malformed/ambiguous inputs, duplicate IDs, unsafe URL forms and replacement output. Literal GitHub commit pins remain unverified URL declarations. The actual twenty-entry estack manifest produced twenty queued records: eighteen URL-declared commits and two honestly unpinned entries.

Verification: 71 tests passed, 0 failed/skipped, retaining all prior 60 cases. The unchanged schema and four original research hashes were verified. Actual Codex skill validation passed; independent artifact review accepted bounded continuation. Exact results, code hashes, real-manifest evidence, the review and the archive and install receipts are build records, omitted from the public edition.

Estack advanced to v0.2.0 with a canonical task starter, three bounded raw-source reviews, lifecycle/recovery guidance and 73 deterministic tests. Two independent authored developer tasks additionally passed six reviewer-owned product checks; they are not a controlled test of Frankenmine effectiveness. No broader catalogue, host, language-pair or model effectiveness qualification is claimed.

The helper uses only Python's standard library; no new dependencies, donor execution, policy mutation or publication was introduced. Full qualification remains governed by evals/LIVE_AGENT_PROTOCOL.md.
